## 一、 核心选型结论摘要

| 评测维度 | mica-ppocr | RapidOCR4j | 选型建议与差异分析 |
| :--- | :--- | :--- | :--- |
| **并发吞吐 (QPS)** | 见下表实测 | 见下表实测 | 两者均基于 ONNX Runtime，在相同 tiny 模型和线程配置下吞吐高度接近 |
| **内存管理 (Native RSS)** | 稳定无泄漏 | 稳定无泄漏 | 进程物理内存主要由 ONNXRuntime/OpenCV Native 堆占用，JVM 堆仅占小部分 |
| **模型管理与依赖** | 需配置模型路径与字典 | **内置默认模型**，开箱即用 | RapidOCR4j 极简依赖；mica-ppocr 支持灵活切换 tiny/small/medium 档位 |
| **业务结构化能力** | **内置 9+ 种证件票据解析** | 纯 OCR 文本提取 | 证件审核/报销场景推荐 `mica-ppocr`，通用识别推荐 `RapidOCR4j` |
| **坐标与定位精度** | 文本行级四点多边形 | **单字/英文词级精确坐标** | 需要字级高亮/双层 PDF 重建推荐 `RapidOCR4j` |
| **生态与框架集成** | **Spring Boot 官方 Starter** | 独立 Java SDK | Spring 体系推荐 `mica-ppocr`，非 Spring/JDK 8 推荐 `RapidOCR4j` |

## 六、 生产环境选型综合建议

1. **如果你的项目是 Spring Boot / 企业微服务，且需要处理证件、发票、营业执照等结构化数据**：
   - **首选 `mica-ppocr`**：开箱提供 Spring Boot Starter，内置 9+ 种常见凭证解析器，支持整图 4 方向纠偏（处理手机倒拍/横拍），模型与代码解耦方便升级。

2. **如果你的项目是通用工具库、或者需要精确字/词级高亮标注、或需要兼容 JDK 8**：
   - **首选 `RapidOCR4j`**：开箱内置模型，无需配置模型文件路径，支持单字/词级细粒度坐标输出，支持调用级热参数覆盖（`ParamConfig`）。

3. **高并发部署与资源配置建议**：
   - OCR 计算主要消耗 CPU 和 Native 物理内存（RSS），JVM 堆占用极少。
   - 容器化部署时，**内存限制（Memory Limit）必须以 Native 物理内存为基准**（建议每路并发预留 300MB~500MB 物理内存），不能仅依赖 `-Xmx`。
   - 多线程并发时建议将 `intraOpNumThreads` 设为 `1` 或 `CPU物理核数/并发路数`，避免算子线程超订导致吞吐下降。
